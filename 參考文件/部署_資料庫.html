DMS V6 Windows 部署：PostgreSQL 資料庫

1. 部署目標

本文件說明在 Windows Server 上建立 DMS V6 使用的 PostgreSQL 資料庫。應用程式實際使用 pg 套件連線，預設資料庫名稱為 dms，預設連接埠為 5432。

正式環境不得讓應用程式使用 postgres 超級使用者。下列範例建立專用登入角色 dms_app。

2. 前置條件

  1. 安裝 PostgreSQL 16 或組織核准版本。
  2. 確認 PostgreSQL Windows 服務已啟動。
  3. 確認 psql.exe 所在目錄已加入 PATH，或使用完整路徑執行。
  4. 準備一組只供 DMS 使用的強密碼。

3. 建立登入角色與資料庫

以 PostgreSQL 管理者身分開啟 PowerShell，先連入預設資料庫：

psql -U postgres -h 127.0.0.1 -p 5432 -d postgres

執行下列 SQL。請先替換密碼，不要沿用範例值：

CREATE ROLE dms_app
  WITH LOGIN
       PASSWORD '請替換成正式環境強密碼';

CREATE DATABASE dms
  WITH OWNER = dms_app
       ENCODING = 'UTF8'
       TEMPLATE = template0;

本專案規範不建立外鍵與命名 CONSTRAINT。資料表的主鍵與資料一致性由既有 DDL 及應用程式流程管理。

4. 建立資料表與索引

依下列順序，使用 dms_app 連入 dms 資料庫，執行各文件「DDL」區段中的 SQL：

  1. schema_department.md
  2. schema_employee.md
  3. schema_dms_admins.md
  4. schema_dms_folders.md
  5. schema_dms_folder_managers.md
  6. schema_dms_folder_acl.md
  7. schema_dms_doc.md
  8. schema_dms_file.md
  9. schema_dms_doc_ver.md
  10. schema_dms_ver_rev.md
  11. schema_dms_audit_log.md

連線命令如下：

psql -U dms_app -h 127.0.0.1 -p 5432 -d dms

若現場已有 department 與 employee 主檔，不可直接覆蓋。必須先比對欄位名稱、資料型別，以及 employee.emp_id、employee.dept_id、department.dept_id 是否符合本專案查詢需求。

5. 建立第一位系統管理者

登入驗證以 employee 為人員主檔，dms_admins 用於判斷系統管理員權限。先依 schema_employee.md 的欄位定義建立員工資料，再依 schema_dms_admins.md 建立管理員資料。

正式匯入前必須確認現有密碼欄位格式符合 dmsV6/lib/server/auth.ts 的驗證邏輯，不可自行改成另一種雜湊格式。

6. 應用程式連線設定

建議設定單一 DATABASE_URL：

DATABASE_URL=postgres://dms_app:URL編碼後的密碼@127.0.0.1:5432/dms
PGPOOL_MAX=10

密碼若包含 @、:、/、# 或 %，必須先做 URL 編碼。也可以不用 DATABASE_URL，改設下列變數：

PGHOST=127.0.0.1
PGPORT=5432
PGDATABASE=dms
PGUSER=dms_app
PGPASSWORD=正式環境密碼
PGPOOL_MAX=10

7. 遠端資料庫設定

資料庫與 Web Server 分開時，才需要調整遠端連線：

  1. 在 postgresql.conf 將 listen_addresses 設為資料庫伺服器實際內網 IP，不要直接使用 *。
  2. 在 pg_hba.conf 只允許 Web Server 的固定內網 IP 連入 dms。
  3. Windows Defender 防火牆只允許該來源 IP 存取 TCP 5432。
  4. 重新啟動 PostgreSQL Windows 服務。

pg_hba.conf 範例：

host    dms    dms_app    192.168.10.25/32    scram-sha-256

8. 驗證

8.1 資料表驗證

psql -U dms_app -h 127.0.0.1 -p 5432 -d dms -c "\dt"

應至少看到第 4 節列出的 11 個資料表。

8.2 應用程式連線驗證

應用程式啟動後，在伺服器本機執行：

Invoke-WebRequest -UseBasicParsing http://127.0.0.1:3000/api/test

若失敗，依下列格式判斷：

  • Status：HTTP 500 或無法連線。
  • Root Cause：資料庫服務未啟動、連線字串錯誤、來源 IP 未被 pg_hba.conf 允許，或資料表尚未建立。
  • Suggested Fix：先用相同帳號執行 psql 連線測試，再檢查應用程式服務所取得的環境變數。

9. 備份與還原

每日備份命令範例：

pg_dump -U dms_app -h 127.0.0.1 -p 5432 -d dms -F c -f C:\DMS\backup\dms.backup

還原至已建立的空白 dms 資料庫：

pg_restore -U dms_app -h 127.0.0.1 -p 5432 -d dms --clean --if-exists C:\DMS\backup\dms.backup

資料庫備份不包含 C:\DMS\storage 的實體文件。資料庫與檔案儲存目錄必須使用同一個備份時間點，否則版本紀錄可能指向不存在的檔案。
