# DMS V6 API 安全與 SQL 優化執行計畫

## 1. 文件資訊

| 項目 | 內容 |
|---|---|
| 文件狀態 | 草案，待使用者修改與核准 |
| 適用專案 | `D:\.我的專案\04.文件管理系統_V6_codex\dmsV6` |
| 目標架構 | 維持現有 Next.js 全端架構 |
| 前端 API 路徑 | 同源 `/api/*` |
| 後端服務位置 | `dmsV6/lib/server` |
| 資料庫 | PostgreSQL |
| 執行方式 | 依批次逐步實作，每一批完成驗證後才進入下一批 |

## 2. 已確認原則

- [x] 維持目前 Next.js 全端架構。
- [x] 不拆分成獨立 API 專案。
- [x] 不以 JWT 取代目前架構作為主要安全措施。
- [x] 前端繼續只呼叫同源 `/api/*`。
- [x] 資料庫、檔案系統及權限邏輯維持於後端。
- [x] 不建立 Foreign Key。
- [x] 不建立額外 Constraint。
- [x] 索引定義內不進行型別轉換。
- [x] `.env.example` 內的資料庫參數目前屬於本機測試資料。
- [x] `storage` 內受到 Git 追蹤的文件目前皆為測試文件。
- [x] 本計畫暫不處理測試資料庫密碼及測試文件的 Git 追蹤問題。
- [ ] 正式部署前，必須另行更換正式資料庫密碼及 `SESSION_SECRET`。

## 3. 執行管制

### 3.1 每一批的固定流程

1. 確認本批次範圍與使用者修改內容。
2. 檢查工作目錄，避免覆蓋既有未提交變更。
3. 僅修改本批次列出的檔案。
4. 執行檔案範圍檢查及 TypeScript 檢查。
5. 從 `dmsV6` 執行 `npm run build`。
6. 執行本批次列出的 API 或資料庫驗證。
7. 回報變更檔案、驗證結果及剩餘風險。
8. 使用者確認後，才進入下一批。

### 3.2 停止條件

遇到下列情況時，不得自行擴大修改範圍：

- 商業規則與現有程式行為衝突。
- 需要修改共用的 `employee.emp_pw` 密碼格式。
- 需要刪除正式文件或資料庫資料。
- 需要變更 IIS、VPN、防火牆或正式網域。
- 需要新增尚未核准的 PostgreSQL 資料表。
- 建置失敗且根因不在本批次修改範圍。
- 發現使用者尚未提交的變更與預計修改內容重疊。

發生錯誤時，必須使用以下格式回報：

```text
Status：
Root Cause：
Suggested Fix：
```

### D-02：來源檔案大小上限

- [ ] C. 改由獨立且不帶 DMS Session Cookie 的預覽網域提供。

建議選擇 A；若 HTML 內容必須執行 JavaScript，改選 C。

### D-04：敏感操作的稽核寫入失敗策略

- [x] A. 稽核寫入失敗時，文件刪除、ACL 修改及封存一併回復。
- [ ] B. 主操作繼續，但必須寫入伺服器錯誤日誌及系統事件紀錄。

建議選擇 A。

### D-05：伺服器端 Session 資料表

- [x] 暫時維持目前簽章 Cookie，只先移除預設密鑰並補強驗證。

## 5. 批次一：API 共用安全基礎

### 5.1 目標

統一 API 的身分驗證、來源驗證、輸入處理、HTTP 狀態碼與錯誤回應。

### 5.2 預計修改範圍

- `dmsV6/lib/server/http.ts`
- `dmsV6/lib/server/auth.ts`
- `dmsV6/lib/server/request.ts`
- `dmsV6/app/api/**/route.ts`
- `dmsV6/next.config.mjs`

### 5.3 執行項目

- [ ] 建立共用 API 錯誤型別或錯誤碼。
  - 狀態：不執行
- [ ] 統一 `400`、`401`、`403`、`404`、`409`、`413`、`415`、`429`、`500` 的使用規則。
- [ ] 未登入請求統一回傳 `401`。
- [ ] 已登入但無權限統一回傳 `403`。
- [ ] 不再將 PostgreSQL、檔案路徑或原始例外內容回傳前端。
  - 狀態：不執行
- [ ] 後端錯誤產生追蹤識別碼。
  - 狀態：不執行
- [ ] 完整錯誤只寫入後端日誌。
  - 狀態：不執行
- [ ] POST、PUT、PATCH、DELETE 驗證 `Origin`。
- [ ] JSON API 驗證 `Content-Type: application/json`。
- [ ] 檢查所有數字識別碼必須為正整數或明確允許的 `0`。
- [ ] 檢查必要字串不可空白並限制長度。
- [ ] 檢查陣列欄位型別、筆數及重複值。
- [ ] 正式環境停用或移除 `/api/test`。
- [ ] 加入 CSP、`nosniff`、Referrer Policy、Permissions Policy 與 Frame 限制。
- [ ] 正式 HTTPS 環境加入 HSTS。
  - 狀態：不執行

### 5.4 驗證項目

- [ ] 未登入存取資料夾 API 回傳 `401`。
- [ ] 無權限修改資料夾回傳 `403`。
- [ ] 無效 JSON 回傳 `400`，不包含內部例外。
- [ ] 非 JSON Content-Type 的異動請求回傳 `415`。
- [ ] 不合法 ID 不會送入 PostgreSQL。
- [ ] 不同來源的異動請求被拒絕。
- [ ] `/api/test` 在正式環境不可使用。
- [ ] `npm run build` 成功。

### 5.5 完成條件

- [ ] 所有 API Route Handler 使用同一套錯誤與驗證規則。
- [ ] 前端既有正常操作未受影響。
- [ ] 正式建置成功。

- `dmsV6/app/api/documents/download/route.ts`
- `dmsV6/.env.example`
- `dmsV6/.env.local`

### 6.3 執行項目

- [x] 依 D-01 設定發布檔案大小上限。
- [x] 依 D-02 設定來源檔案大小上限。
- [x] 在 Base64 解碼前估算大小。
- [x] 解碼後再次確認實際大小。
- [x] 拒絕空檔案及格式不合法的 Base64。
- [x] 交叉驗證副檔名、MIME 與檔案特徵碼。
- [ ] PDF 浮水印處理前檢查檔案大小。
- [x] 依 D-03 實作 HTML 預覽策略。
- [ ] HTML 預覽回應加入獨立 CSP。

## 7. 批次三：文件與資料夾交易一致性

### 7.3 執行項目

- [ ] 上傳新版前在交易內鎖定 `dms_doc`。
- [ ] 撤回最新版前在交易內鎖定 `dms_doc`。
- [ ] 刪除第一版前在交易內鎖定 `dms_doc`。
- [ ] 廢止文件前在交易內鎖定 `dms_doc`。
- [ ] 建立子資料夾前鎖定父資料夾。
- [ ] 刪除空資料夾前鎖定目標資料夾。
- [ ] 封存資料夾前鎖定目標資料夾。
- [ ] 將異動前權限檢查移入相同交易。
- [ ] 記錄交易期間新建立的實體檔案。
- [ ] 資料庫回復後刪除本次新增的實體檔案。

### 7.4 SQL 格式要求

SQL 必須保持多行、易讀且欄位對齊，例如：

```sql
SELECT dd_id
  FROM dms_doc
 WHERE dd_id = $1
   FOR UPDATE
```

### 7.5 併發驗證

- [ ] 上傳新版與撤回同時發生時，結果一致。
- [ ] 刪除第一版與上傳新版同時發生時，不會誤刪文件。
- [ ] 刪除空資料夾與建立子資料夾同時發生時，不會留下異常階層。
- [ ] 交易失敗後不留下孤兒檔案。
- [ ] `npm run build` 成功。

### 7.6 完成條件

## 8. 批次四：Session 與登入防護

### 8.1 目標

讓登入狀態可以由伺服器撤銷，並限制暴力登入。

### 8.2 預計修改範圍

- `dmsV6/lib/session.ts`
- `dmsV6/lib/server/auth.ts`
- `dmsV6/app/api/login/route.ts`
- `dmsV6/app/api/logout/route.ts`
- `dmsV6/app/api/session/route.ts`
- `dmsV6/lib/server/auditService.ts`
- 新增 Session 與登入失敗紀錄相關 schema 文件。

### 8.3 Session 資料表規則

若 D-05 同意新增資料表，需符合：

- [ ] 不建立 Foreign Key。
- [ ] 不建立額外 Constraint。
- [ ] Session ID 只保存雜湊值。
- [ ] 保存使用者帳號。
- [ ] 保存建立時間與到期時間。
- [ ] 保存最後活動時間。
- [ ] 保存撤銷時間與撤銷原因。
- [ ] 保存 IP 及 User-Agent 摘要。
- [ ] 建立必要的普通索引，不在索引內做型別轉換。

### 8.4 執行項目

- [ ] Cookie 只保存隨機 Session ID。
- [ ] API 每次由 PostgreSQL 驗證 Session。
- [ ] 敏感操作重新取得目前使用者角色。
- [ ] 登出立即撤銷 Session。
- [ ] 離職、停權或權限取消後舊 Session 不再有效。
- [ ] 正式環境缺少必要 Session 設定時停止啟動。
- [ ] HTTPS 環境使用 Secure Cookie。
- [ ] Session Cookie 維持 HttpOnly。
- [ ] 加入帳號及 IP 單位的登入失敗限制。
- [ ] 加入短時間連續失敗延遲。
- [ ] 加入暫時鎖定及自動解鎖時間。
- [ ] 登入成功後清除失敗計數。
- [ ] 登入成功、失敗、鎖定及撤銷均寫入稽核。

### 8.5 驗證項目

- [ ] 偽造 Session ID 無法登入。
- [ ] 登出後舊 Session 無法繼續使用。
- [ ] 權限取消後舊 Session 無法維持原權限。
- [ ] 過期 Session 被拒絕。
- [ ] 達到失敗次數後登入受到限制。
- [ ] 不同 IP 與不同帳號的限流規則正確。
- [ ] `npm run build` 成功。

### 8.6 MD5 處理

- [ ] 依 D-06 決定是否進行密碼雜湊遷移。
- [ ] 未確認其他系統相容性前，不修改 `employee.emp_pw`。
- [ ] 若要遷移，另建立獨立計畫，不併入本批次直接修改。
